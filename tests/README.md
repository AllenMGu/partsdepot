# 回归测试

PR 评审修复项的回归测试套件（黑盒 HTTP + 进程内单元），本地 SQLite 即可运行，**无需 PostgreSQL**。

## ⚠️ 安全警告（必读，五轮评审 P0）

**切勿将生产连接串传给本目录任何脚本。** 这些脚本会对目标库执行破坏性操作：

- `test_suite.py` 会**删除 config 表的 ldap_* 行**（LDAP 撤销场景）
- 所有脚本都会新建/删除仓库、货物、库位、库存、单据等**业务数据**
- `pg_concurrency.py` 还会 **DROP `stock` 的 (仓库,货物,库位) 复合唯一约束**

为此内置了**测试库安全护栏**（`tests/test_db_guard.py`，三个入口在启动服务前强制校验）：

| 规则 | 行为 |
|---|---|
| 数据库名在黑名单（`warehouse_db` 已知生产库名、`postgres` 默认维护库） | **直接拒绝，任何环境变量都无法豁免** |
| 核心业务表（用户/仓库/货物/库位/库存/配置/单据）任一有数据 | 拒绝（退出码 3），并打印非空表清单 |
| 无法连接目标库 | 无法确认其为空库 → 拒绝（fail closed） |
| 显式设置 `WMS_ALLOW_NONEMPTY_TEST_DB=1` | 跳过"非空"检查（**不豁免黑名单**），用于已确认可整体丢弃的库 |

**推荐用法**：为测试**单独建一个可整体丢弃的临时数据库**，并配一个**受限账号**
（仅授权该测试库，不给任何生产库权限），再把该账号的连接串传给脚本。
每次运行前确保该库为空（或整体删除重建）。

## 运行

```bash
pip install -r requirements.txt
bash tests/run_regression.sh
```

- 自动启动临时服务（端口 8091，可用 `PORT` 覆盖）、全新 `tests/regression.db`
- 依次运行：
  - `test_suite.py` —— 黑盒 HTTP 回归（72 项检查）
  - `ldap_revoke_unit.py` —— 进程内验证 LDAP 配置加载（全局值清除、env>DB 优先级）
- 全部通过则退出码 0

## 在 PostgreSQL 上运行（评审要求：行级锁/咨询锁语义真实生效）

默认用 SQLite。若要验证真实 PG 的行级排他锁与 `pg_advisory_xact_lock`，
把 `WMS_DATABASE_URL` 指向一个**空** PG 库即可（脚本会先用安全护栏校验该库为空，再用该 URL 起服务并跑同一套 72 项）：

```bash
# 例：本地已有一个空的 postgres 库 wms_pgtest
export WMS_DATABASE_URL="postgresql://postgres:@/wms_pgtest?host=/path/to/pgsocket"
bash tests/run_regression.sh
```

另附**并发复测**脚本，专门验证"并发建行/并发完成"路径（评审重点）：
它会先 **DROP 掉 `stock` 的 (warehouse,goods,location) 复合唯一约束**，
模拟"生产库尚无该约束"的现状，再断言"恰好一条库存行"——
从而证明防重复靠的是代码里的行级锁+咨询锁，而不是数据库约束兜底：

```bash
WMS_DATABASE_URL="postgresql://postgres:@/wms_pgconc?host=..." \
  .venv/bin/python tests/pg_concurrency.py
```

七个场景（共 25 项检查，**25/25 通过**；A~C 为建行/完成并发，D~G 为"明细写入∥提交/完成"强制交错）：
- **A** 两线程并发"首次入库"同一 (货物,库位) → 两单均 200，**恰好 1 条库存行**，库存=3+4=7
- **B** 两线程并发"完成同一盘点单"（基线0、无库存行）→ 恰一个 200、另一个 400，**恰好 1 条库存行**
- **C** 盘点完成 ∥ 首次扫码入库 并发同组合 → 无 500，**恰好 1 条库存行**
- **D** 入库 新增明细 ∥ 提交 → 新明细**要么随提交过账**（明细2条、库存=2+3=5），**要么被 400 拒绝**（明细1条、库存=2），不允许中间态
- **E** 盘点 录入明细 ∥ 完成 → 新明细**要么随完成过账**（2条、两个组合均入账），**要么被 400 拒绝**（1条），不允许已完成单据挂未过账明细
- **F** 出库 新增明细 ∥ 提交 → 新明细**要么随提交扣减**（2条、库存=4-3=1），**要么被 400 拒绝**（1条、库存=4-1=3）
- **G** 入库 编辑明细 ∥ 提交 → 编辑**要么生效并过账**（库存=9），**要么被 400 拒绝后按原值过账**（库存=2）

## 覆盖的修复项（对应 PR #1 三轮评审）

| 评审项 | 测试 |
|---|---|
| P0 出库拆单绕过库存校验 | 拆单 7+7 → 400 且库存未变 |
| P0 重复提交/并发重复提交 | 400 拒绝 + 并发不变量（非负、扣减=成功数） |
| P0 盘点期间出入库被覆盖 | 基线≠当前 → 409，库存不被覆盖；重盘后可过账（含负差异） |
| P0 编辑入库明细无跨仓校验（三轮新增） | 改到 B 仓库位 → 400；同仓 → 200 |
| P1 扫码单部分明细失败整体 500 | 明细错误 → 400，无单据无流水 |
| P1 LDAP 未配置登录 500 / 配置泄露 | 401 降级；配置接口无内部值；**撤销后旧全局值被清除**（进程内） |
| P1 新用户零仓库授权 | 登录、仓库列表为空、扫码 403 |
| P1 库位管理越权 | 操作员建/改库位 403；管理员跨仓改仓 400 |
| P1 入库编辑明细 500（单价可选） | 表头/明细编辑 200，省略单价回退物料价 |
| P1 出库明细编辑 500 + 无跨仓校验（三轮新增） | 省略单价 200（非 500）；改到 B 仓库位 400 |
| P1 入库单同(货物,库位)多条明细唯一约束 500（三轮新增） | 两条明细提交 200，库存=合计 |
| P0 盘点完成"无库存行"建行无锁（四轮新增） | 基线=0 实盘6 完成→新建库存行=6；重复完成→400 且不二次过账（单头锁+咨询锁串行化） |
| P0 明细写入未与提交共用单头锁（五轮新增） | 11 个写接口（入/出库明细新增/编辑/删除、盘点录入、入/出库表头编辑、入/出库单据删除）均先 `lock_order_header` 锁单头再在锁内复核状态；终态单据新增/编辑明细→400（顺序）+ 并发交错 D~G（新明细要么随提交/完成过账、要么 400 拒绝，两次运行各命中一个分支） |
| P0 测试脚本可误伤现有数据库（五轮新增） | `test_db_guard.py` 护栏：黑名单库名硬拒（逃生开关不豁免）；核心表非空拒绝（可 `WMS_ALLOW_NONEMPTY_TEST_DB=1` 豁免）；不可达 fail-closed；三个入口（run_regression.sh / test_suite.py / pg_concurrency.py）启动服务前强制校验 |
| P1 删除草稿后单号复用撞号 | 新建=全局最大尾号+1 |
| 其他 | JWT 30 分钟、管理员自举、README/静态托管 |

## 说明与限制

- 并发用例在 SQLite 下验证**不变量**（库存非负、扣减与成功数一致、终态拒绝明细写入）；
  行级排他性（恰好一个 200、新明细要么过账要么 400 拒绝）依赖 PostgreSQL 的 `FOR UPDATE` + 咨询锁。
  **已在真实 PostgreSQL 上复测**（回归 72/72 + 并发 25/25，见上文"在 PostgreSQL 上运行"），
  上线前仍建议在生产同构环境按本套件场景复核。
- `xlsxwriter` 已列入 `requirements.txt`（盘点 Excel 导出 `engine='xlsxwriter'` 依赖）。
- 测试凭据（admin/Admin-Test-2026 等）仅用于本地临时实例，不写入生产。
